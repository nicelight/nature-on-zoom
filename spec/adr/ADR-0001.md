# ADR-0001: Выбор технологии WebSocket-сервера

**Статус:** accepted  
**Дата принятия:** 2025-12-28  
**Решает:** T 4.1 — CONSULT: выбор Python vs Node.js

---

## Контекст

Для имитации стримингового трафика нужен минимальный WebSocket-сервер, который:
- Принимает heartbeat ping/pong соединения
- Отвечает на HTTP-запросы метаданных стримов
- Работает стабильно на VPS ALma Linux

## Альтернативы

### Вариант A: Python с библиотекой `websockets`

```python
# ws_server.py
import asyncio
import websockets
import json
from aiohttp import web

async def handle_ws(websocket, path):
    async for message in websocket:
        data = json.loads(message)
        if data['type'] == 'ping':
            await websocket.send(json.dumps({
                'type': 'pong',
                'timestamp': data['timestamp'],
                'serverTime': int(time.time() * 1000)
            }))

# ...
```

**Плюсы:**
- Python уже установлен на большинстве Linux-систем
- Меньше зависимостей
- Легко читаемый код
- Подходит для простого продакшена

**Минусы:**
- Потребляет больше памяти (~50-100 MB)
- Немного медленнее Node.js для высоких нагрузок

---

### Вариант B: Node.js с библиотекой `ws`

```javascript
// ws_server.js
const WebSocket = require('ws');
const wss = new WebSocket.Server({ port: 8765 });

wss.on('connection', (ws) => {
  ws.on('message', (message) => {
    const data = JSON.parse(message);
    if (data.type === 'ping') {
      ws.send(JSON.stringify({
        type: 'pong',
        timestamp: data.timestamp,
        serverTime: Date.now()
      }));
    }
  });
});
```

**Плюсы:**
- Высокая производительность для WebSocket
- Меньше памяти (~30-50 MB)
- Event-driven архитектура

**Минусы:**
- Требует установки Node.js на сервере
- Дополнительный runtime

---

### Вариант C: Cloudflare Workers (serverless)

```javascript
// worker.js
export default {
  async fetch(request, env) {
    const upgradeHeader = request.headers.get('Upgrade');
    if (upgradeHeader === 'websocket') {
      return handleWebSocket(request);
    }
    return handleHTTP(request);
  }
}
```

**Плюсы:**
- Нет необходимости в собственном бэкенде
- Автоматическое масштабирование
- Бесплатный tier (100k запросов/день)

**Минусы:**
- Cloudflare WebSocket имеет ограничения
- Сложнее отладка
- Зависимость от внешнего сервиса

---

## Рекомендация

**Вариант A: Python** — для MVP это оптимальный выбор:
1. Минимальные требования к серверу
2. Простота развёртывания
3. Достаточная производительность для задачи

При необходимости можно мигрировать на Node.js или Cloudflare Workers.

---

## Вопрос к тимлиду

**Какой вариант выбираем?**
- [ ] A: Python (websockets + aiohttp)
- [ ] B: Node.js (ws + express)
- [ ] C: Cloudflare Workers

---

## Решение

**Выбор:** ✅ **Вариант B: Node.js (ws + express)**

**Причины:**
1. Высокая производительность для WebSocket-соединений
2. Event-driven архитектура идеально подходит для real-time
3. Меньшее потребление памяти (~30-50 MB)
4. Единый стек JS на фронте и бэке

**Последствия:**
- Необходимо установить Node.js на VPS ALma Linux
- Использовать библиотеки: `ws` для WebSocket, `express` для HTTP API
- Systemd unit для автозапуска
